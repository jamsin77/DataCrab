# 文档规则提取入库

## 功能说明
从 PDF / Word（.docx）格式的规则文档中提取结构化规则，写入目标数据源的规则知识库表。支持自动判断规则是否已存在（按规则编号 rule_code），已存在的规则会被新规则覆盖，不存在的规则追加写入。

### 提取策略
- 提取内容之前，先通读整个文档，理解全文结构与语义，再开始解析提取。
- 正文内容（非表格部分）提取为一张表；文档中的各个表格可以单独提取成一张表。
- 表格行如果表达同一语义或需要合并，会按语义自动合并，避免规则被拆散。
- 跨越多页的表格会按语义合并成一张表：有表格名称时按表格名称聚合，无表格名称时自动合并到上一个表格。
- 文档包含正文和多个表格时，每个提取单元分别生成独立表，各表名字根据内容语义自动生成（如正文表以文档主题命名，表格表以表格标题或表格内容语义命名），避免不同提取单元的内容混在一起。
- 提取表格时，表头尽量与表格保持一致，表的内容尽量与表格单元保持一致，避免改写或概括原文；关键数值、阈值、判据必须逐字保留。
- **表格名字必须使用文档中该表格的完整名称（如"表1 设备状态信息"），包括表号、表名及同一行或相邻行的补充说明，不得截断、不得只取表号或部分表名。**
- **表格的列数和行数必须保持一致：缺失列补空值，多余列内容合并到该行最后一列（用分号分隔），不得丢弃有效数据。**
- 如果表格有序号，相同序号的行按照语义进行合并形成一行，确保同一规则内容不因分页、分行或转置被拆散；后处理合并以「相同 rule_code + 同一表格归属」为条件，避免不同表格中恰好相同序号的独立规则被错误合并。
- **表格中存在的合并单元格（垂直合并）列，提取时必须补全列值：该列为空时用上方最近非空值回填，确保每一行该列都有明确值。**
- **如果某一行的某一列存在与表头不一致的子列（多级表头展平不彻底导致的重复列名或子列分解），必须按行把各子列内容用分号拼接，确保不丢失信息。**
- 脚本在 LLM 提取后还会执行一次后处理合并：对相同规则编号（rule_code）且同属一个表格的条目，无论规则名称是否完全一致，都会自动合并适用字段、检查逻辑和说明字段，进一步确保同一规则最终只保留一条完整记录。合并时若各片段某字段值一致则原样保留（保持表头/单元格原文），不一致才拆分或拼接。
- 如果目标数据源是图数据库，按照图数据库的格式定义表（节点、关系、属性），提取出的规则内容会转换为图模型结构存储。
- 写入时可以提示选择追加还是覆盖原有已经提取的知识（通过 if_table_exists 参数控制）。

提取的规则字段包括：
- `rule_code`：规则编号（唯一键）
- `rule_name`：规则名称
- `category`：规则分类（标准 / 质量 / 安全）
- `applicable_fields`：适用字段
- `format_regex`：格式正则表达式
- `check_logic`：检查逻辑描述
- `severity`：严重等级（info / warn / error / critical）
- `description`：规则详细解释
- `source_document`：来源文档路径
- `updated_at`：更新时间

## 使用方式
```
解析文件 "/data/rules/风控规则.pdf" 并写入 "凭证检索库" 的 rules_knowledge_base 表
```
```
从 "/data/rules/贷款规则.docx" 提取规则，更新到 "凭证检索库" 的 rules_knowledge_base 表，覆盖已存在的规则
```
```
解析多个文件：/data/rules/规则1.pdf,/data/rules/规则2.docx，写入知识库
```

## 参数规范

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `document_paths` | str | ✅ | - | PDF / Word 文件路径，多个用英文逗号分隔 |
| `target_datasource_name` | str | ✅ | - | 目标数据源名称（用于写入规则表） |
| `target_table_name` | str | ✅ | - | 目标主表名；当提取出多张表时，其余表名根据内容语义自动生成 |
| `if_table_exists` | str | ❌ | replace | 写入策略：fail/append/replace/overwrite/truncate 等，用于控制追加或覆盖已有知识 |

> 说明：目标数据源和表名为必填参数，用户需明确指定。如果目标表不存在，脚本会自动创建。若目标数据源为图数据库，表结构会按图数据库格式定义。

## 脚本说明

| 脚本 | 说明 |
|------|------|
| `main.py` | 核心处理脚本：解析文档、LLM 提取规则、同序号行后处理合并、合并单元格补全、子列拼接、列数归一化、多表/图模型写入 |

## 数据质量检查规则

以下检查规则已在 `rules.md` 中定义，脚本在写入前会通过 `check_skill_rules` 自动执行：

| 规则 ID | 检查要点 |
|---------|----------|
| SKILL-DRE-001 | 表格名称必须使用文档中的完整全名，不得截断 |
| SKILL-DRE-002 | 表格列数与行数必须保持一致 |
| SKILL-DRE-003 | 有序号表格必须按序号归并为一行 |
| SKILL-DRE-004 | 垂直合并单元格列必须补全列值 |
| SKILL-DRE-005 | 与表头不一致的子列必须按行拼接 |

## 注意事项
- PDF 解析需要环境安装 `pypdf` 或 `PyPDF2` 库；Word 解析需要 `python-docx` 库。
- 如果所有文档解析失败，脚本会返回 `success=False` 并报错。
- 规则覆盖以 `rule_code` 为唯一键，请确保 LLM 提取的规则编号在文档中唯一或可自动生成不冲突的编号。
- 正文与多个表格会生成多张规则表，表名按照语义自动生成；写入时可根据目标表已有数据情况选择追加或覆盖。
- 若目标数据源为图数据库，请确认目标数据源类型支持图模型写入，表结构会按图数据库格式（节点/关系/属性）定义。
- 表格名称完整性、列数行数一致性、序号归并、合并单元格补全、子列拼接等质量要求会在写入前通过 check_skill_rules 自动检查。
