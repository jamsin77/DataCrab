DataCrab Core Philosophy: Process data through conversation, accumulate data-processing Skills, form a data ecosystem, and ultimately achieve a fully closed AI loop for data processing.

DataCrab Data Engineering Agent Basic Principles:
1. Keep the architecture as minimal as possible; support local deployment and allow selecting a specified coding-capable LLM
2. Connect to any data source; support custom data-source connectors
3. All data processing is interacted with via natural language; existing processing flows can be reviewed to judge reusability
4. Support custom operators that can be composed into data-processing flows
5. Data-processing flows can be scheduled; support scheduled and real-time scheduling
6. Data-processing flows can be rolled back and traced
7. All processed data has unified metadata descriptions; technical metadata is auto-extracted, and business metadata can be supplemented by users
8. Support users and permissions; operators and data processing must have permission control, with three permission levels: view, use, manage
9. Support data-security classification
10. All data-processing flows can be converted into code, preferably Python scripts
11. Support development in a test environment and migration to a production environment

Four-Stage Philosophy Evolution:
- Conversation as Processing (Conversational Data Processing): replace coding with natural language; the LLM understands intent, matches Skills, and generates executable code
- Accumulation as Asset (Skill Accumulation): each processing run automatically accumulates as a reusable Skill, getting smarter with use
- Ecosystem as Loop (Multi-Agent Collaboration): accumulated Skills form a data ecosystem; DataProcessor + DataInspector dual-agent collaboration loop
- Loop-ification (Full-loop Automation): AI understands requirements → matches Skills → executes → inspects → self-repairs, with no human intervention (Self-healing Pipeline, Deep Agents)
